# 게임 수정 기록과 배포 전 체크리스트 (모든 게임 공통)

머지관 「소라섬 등불 이야기」에서 사용자(아내·딸이 휴대폰으로 플레이)가 알려 준 문제에서 시작했습니다. **이 규칙은 아리채 오락실의 모든 게임(머지관·별나침반·올림픽관 등)과 앞으로 만들 게임에 똑같이 적용합니다.**
**어떤 게임이든 고치거나 새로 만들기 전에 아래 체크리스트를 먼저 확인하세요.** (머지관 전용 항목은 다른 게임에 맞게 바꿔 적용: 예) 시험 명령, 저장 방식)

## 2. 다음부터 지킬 규칙 (배포 전 체크리스트)

### 화면
- [ ] **짧은 화면에서 꼭 확인**: 340×600, 360×640, 378×660(크롬 주소창), 390×740, 412×915, 그리고 '글씨 크게'. 판·카드·아래 칸·팝업이 겹치지 않을 것.
- [ ] 높이는 `100dvh` + `visualViewport` 로 계산. 고정 px 높이 가정 금지.
- [ ] 연출(fx) 요소는 `pointer-events: none`. 팝업 위로 올라오지 않게 z-index 확인. 버튼 안 이미지는 크기를 꼭 지정.
- [ ] 팝업·시트는 바깥을 톡하면 닫히게. 말풍선은 몇 초 뒤 자동으로 사라지게.
- [ ] 화면의 숫자(HUD)는 실제 상태에서 나와야 함. "잠시 멈춤" 상태에는 반드시 시간 제한을 둘 것.

### 저장
- [ ] **저장을 덮어쓰기 전에 이전 기록을 항상 보관** (버전 변환, 읽기 실패, 서버·코드 불러오기, 처음부터 하기).
- [ ] 읽지 못한 저장으로 새 판을 만들어 덮어쓰지 말 것. 서버 기록이 더 앞서면 묻기.
- [ ] 저장 형식을 바꾸면 **옛 코드로 만든 저장**으로 변환 시험을 돌릴 것.
- [ ] JS·CSS 는 배포마다 새 버전을 받게(버전 확인/캐시 무력화). 서비스 워커는 그림도 '서버 먼저'.

### 그림
- [ ] 새로 만든 `static/img/**` 파일은 **`git add` 했는지 확인** (untracked 는 배포 안 됨).
- [ ] 가짜 글자·워터마크 검사.
- [ ] '고치기 전/후'는 **'후' 그림을 Kontext 로 부숴서 '전'을 만들기** (구도·좌표 유지). "어둡게 하지 말 것, 확대하지 말 것"을 프롬프트에 명시하고 밝기를 비교 검사.
- [ ] 건물 스프라이트는 같은 각도·같은 seed, 발밑 기준점으로 배치하고 접지 그림자를 깔 것. **확대한 화면으로 스크린숏을 찍어** 기단이 평평한 땅(돌담·비탈 아님) 위에 있는지, 그림자가 기단에 붙었는지 6지역 모두 볼 것. 좌표는 `?edit=1` 도구로 실제 그림에 맞춰 찍기.
- [ ] **방향이 있는 것(다리·선착장·계단·울타리)은 지형 방향과 맞는지** 확인: 다리는 물을 가로질러야 하고(물이 다리를 따라 흐르면 안 됨), 울타리는 둘레 방향을 따라 · 모양 3가지 모두. 지도에 그려진 자리(웅덩이·집터)에 놓는 그림은 그 자리 가운데·같은 크기로.
- [ ] 비슷해 보이는 물건(예: 씨앗 항아리 vs 꽃씨 주머니)은 모양·색을 확실히 다르게.

### 밸런스
- [ ] 동전을 쓰는 기능은 **동전이 적은 초반 상태(10~50개)로 직접 시험**. 하루 무료 횟수 고려.
- [ ] 동전·소라별이 드는 것은 **사기 전에 '○○을(를) 동전 N개에 살까요?'로 묻기** (상점·건물 모양·발생기 강화).

### 진행 방식
- [ ] 같은 파일을 고치는 에이전트는 한 번에 하나. 그림 생성과 코드는 폴더가 다르면 동시에 가능.
- [ ] 배포 전: `node tools/merge_test.js` 통과 + `python -c "import server"` + 위 화면 크기 확인.
- [ ] 배포 전: `python tools/merge_hitcheck.py` (정적 서버 9432) → 폰 크기마다 판 63칸이 다 자기 칸으로 톡 되는지 + 아랫줄 발생기 진짜 터치. 다른 게임도 버튼·칸이 많은 화면은 같은 방식으로 점검.
- [ ] 사용자가 보낸 스크린숏 문제는 같은 종류가 다른 곳에도 있는지 전체 점검.
- [ ] **떠 있는 요소(알림·말풍선·배지·고리)는 '보일 때'와 '사라진 뒤(투명·opacity 0)' 둘 다** 판·버튼을 덮지 않는지 elementFromPoint 로 확인. 투명해진 요소에 `pointer-events: auto` 가 남으면 안 됨.
- [ ] 칸 점검은 빈 칸만이 아니라 **특수 칸(상자 열기!/기다림·거품·그물·발생기)과 알림·배지를 띄운 상태**로, 진짜 터치 톡 후 '맞는 동작'까지 확인 (`merge_hitcheck.py`).
- [ ] 칸 안 표시(링·배지·숫자)는 **칸 안쪽에만** — 음수 위치·원형 마스크로 칸 밖으로 번지지 않게. 가장 작은 칸(340×600·글씨 크게)에서 확대 스크린숏.
- [ ] 꾹 누르기 같은 새 손동작은 짧은 톡·끌기 규칙을 깨지 않는지 시험(점검 도구의 CDP 진짜 터치).
